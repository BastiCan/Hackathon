# Implementation Plan

**Alcance y decisiones de edición.** Se modificará exclusivamente `.kiro/specs/kindergarten-observation-platform/design.md`; `backend/`, `frontend/`, `Dockerfile` y `render.yaml` son un demo y no se usarán para limitar ni justificar la arquitectura objetivo. Se preservarán la estructura general, las reglas pedagógicas no afectadas y los conteos 20/80/500/9/90/2950/8850. Para cerrar vacíos secundarios se adoptan estas decisiones conservadoras: (a) la arquitectura objetivo nombrará PostgreSQL como base relacional durable de API y cola, porque debe soportar reinicios, bloqueos de trabajador e idempotencia sin depender de un proceso o disco local; (b) “exactamente una vez” se expresará como una sola aceptación lógica de cliente a backend mediante `Idempotency-Key`, y ejecución reintentable con efectos idempotentes en el trabajador, sin prometer semántica imposible sobre llamadas externas; (c) la corrección de transcripción se hará con `PUT /api/capturas/{id}/transcripcion`, autorizada y auditada antes de confirmar; (d) la transcripción completa se conserva durante procesamiento/revisión y se elimina según retención, como máximo 24 h después de terminar por defecto, mientras la observación confirmada conserva solo `nota_breve` y el fragmento de respaldo necesario; (e) las notificaciones serán internas, detectadas por polling de bandeja cada 30 s, con notificación del navegador solo opcional y consentida. El repositorio no define un lint o build documental en `README.md`; por ello cada verificación combinará revisión del render Markdown/Mermaid con una comprobación estructural local, y la última tarea hará la auditoría semántica completa.
